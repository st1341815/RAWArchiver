## 四、红线级 bug 与修复

### 现象

preview 中，无 EXIF 的 `IMG_0002.JPG` 被解析为 `date=今天 / date_from=system`，会被归档到 `YYYYMMDD/`，而非跳过。

### 根因

`resolve_date()` 的 ExifTool 分支，命令无条件带 `-FileModifyDate`，结果循环无条件检查 `'System:FileModifyDate'` —— 等于把「文件修改时间兜底」用到了照片上，使照片读不到 EXIF 时仍拿到 mtime 日期，永远到不了 `return (None, 'unknown')` 的跳过分支。**PDF 第二部分同样存在此 bug**（两版共有）。

### 修复（`scripts/raw_archiver.py`）

```python
# 修复前
cmd = _et_run_prefix(binp) + ['-j', '-G1', '-n', '-m',
                             '-CreateDate', '-DateTimeOriginal', '-MediaCreateDate',
                             '-TrackCreateDate', '-FileModifyDate', path]
...
for k in ('ExifIFD:CreateDate', 'ExifIFD:DateTimeOriginal',
          'QuickTime:CreateDate', 'QuickTime:MediaCreateDate',
          'System:FileModifyDate'):

# 修复后：FileModifyDate/mtime 只允许视频
et_tags = ['-CreateDate', '-DateTimeOriginal', '-MediaCreateDate', '-TrackCreateDate']
et_keys = ('ExifIFD:CreateDate', 'ExifIFD:DateTimeOriginal',
           'QuickTime:CreateDate', 'QuickTime:MediaCreateDate')
if video:
    et_tags.append('-FileModifyDate')
    et_keys += ('System:FileModifyDate',)
cmd = _et_run_prefix(binp) + ['-j', '-G1', '-n', '-m'] + et_tags + [path]
...
for k in et_keys:
```
